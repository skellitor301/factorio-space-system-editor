Factorio Space System Editor Help

Getting started & saved state

Factorio Space System Editor is a visual planning tool for Factorio-style space-system layouts. Coordinates, route lengths, solar values, temperatures, orbital relationships, colors, and view state are editable planning data.

  • The current layout autosaves in this browser and is restored the next time the editor is opened.
  • If no valid autosave exists, a fresh editor starts with a randomized system instead of an empty layout.
  • Drag a valid layout JSON file anywhere onto the editor window to load it.
  • The first star is permanent and cannot be deleted. Other node types may be used as fixed or movable anchors depending on the layout being designed.
  • The Export Preview on the right is editable. Press Ctrl+Enter in it to apply valid edited JSON back to the visual editor.
  • Launcher menu: the ☰ menu is intentionally short. New, Edit, Save / Open, and View each open their own window; Help and About follow them directly.
  • New: enter a system name and create a clean system, or generate a randomized system. Creating/generating a system does not replace or reset the active Solar / Temperature model. Random generation uses that preserved active model: planet orbits are placed at model-consistent suggested stellar distances, every generated planet receives matching temperature, Solar power in orbit, and Solar power in atmosphere values, moons use their actual stellar distance for the same three values, and generated route distances match geometry.
  • Edit: change the system title, reset the current layout, configure Systems and Solar/Temp file locations, use Set both to editor directory, and edit the active Solar / Temperature model calculation values.
  • Save / Open: contains the two-tab JSON Library for Systems and Solar / Temp Models. Both tabs use the same dropdown plus Save, Load, Copy JSON, and Paste JSON controls.
  • View: contains the editor theme, global live-route behavior, and independent map-overlay toggles. Show star-distance / solar guides controls current measurement rulers/diagnostics only; Show contextual suggested orbit distances controls suggested orbit rings/ghosts; Show suggested route distances controls route target spines/caps/labels.
  • File locations: pasted paths are stored as labels only; browser security does not allow a typed local path to grant filesystem access. Use the folder button to authorize the actual directory.
  • Set both to editor directory: browsers cannot discover or authorize the HTML file's parent directory automatically. This button opens a folder picker and asks you to select the folder containing the editor, then uses that authorized folder for both system and model files.
  • Draggable windows: New, Edit, Save / Open, View, Help, and About can be moved by dragging their title bars. This lets you keep the working map visible while changing settings that affect the map.
  • Project repository: About → GitHub Repository ↗ opens the public project repository in a new tab for source code, issues, forks, and other GitHub project actions.
  • Information icons: hover or focus an i icon to open its explanation in a detached page-level tooltip above the menu windows. The tooltip is not part of the dialog's scroll area, so long explanations cannot expand/clamp the parent window or create a disappearing scrollbar. The tooltip automatically chooses an on-screen side of the icon and can be scrolled directly if its content is taller than the viewport.
  • When the browser supports the File System Access API, approved folder handles are remembered with IndexedDB. If direct folder access is unavailable, Save falls back to downloads and Load uses normal file import; browser-saved custom models still work.
  • Use ☰ → About for build metadata and the built-in version changelog.
Map navigation
  • Mouse wheel: zoom around the cursor.
  • Drag empty canvas: pan.
  • W A S D: pan by keyboard.
  • Fit: frame all nodes and orbit rings.
  • Home: restore the default viewport.
  • Drag a node: move it. Drag an orbit ring: resize it live.
  • Select a star first, then drag its graphic/outline to resize the star.
Nodes, orbital parents & snapping

Planets, moons, and points can be orbital children. Their relationship is stored explicitly as a parent node plus assigned orbit.

  • When a Planet, Moon, or Point touches/snaps to an eligible orbit, it immediately adopts that orbit and the orbit anchor as its orbital parent.
  • A valid orbit attachment always overrides the 0.1-unit coordinate grid. Multiple eligible nodes can therefore attach at different positions around the same orbit without the grid preventing the snap.
  • Snap priority is: valid object/orbit attachment first, then the 0.1 map-unit precision grid. Holding Shift temporarily bypasses both; releasing Shift during an active move or resize immediately reevaluates the available snap targets.
  • Pull an attached child clear of all eligible rings and it immediately becomes Unattached.
  • Move it onto a different orbit and it immediately adopts the new parent/orbit.
  • Hold Shift while dragging for temporary free movement. Releasing Shift during the drag immediately snaps the node to the nearest valid target: an attachable orbit if it is closer, otherwise the nearest 0.1 map-unit grid point.
  • Moving a parent carries its attached descendants with it.
  • Node cards can be dragged in the sidebar to reorder them. Their order is preserved in autosave and exported JSON.
  • Double-click a node name in the sidebar or on the map to rename it.
  • Node-card X/Y coordinates are directly editable: double-click either coordinate number to replace it with an inline text field, then press Enter or ✓ to apply. Escape cancels.
  • Derived changes are synchronized across the interface immediately. For example, snapping or orphaning a child updates its Orbital parent, Assigned orbit, orbit name, coordinates, and relevant sidebar displays without requiring reselection.
Orbit rings & precision
  • Select a node and press Add Orbit to create an orbit centered on that node.
  • If Add Orbit is used with no node selected, the map enters anchor-pick mode; click the desired node or press Esc to cancel.
  • Orbit radius can be authored in map units or exact km.
  • Mouse resizing snaps orbit radius in 0.1 map-unit increments. In km mode the step is the exact km equivalent using the current layout scale. Hold Shift for temporary free resizing; releasing Shift mid-resize immediately snaps the radius to the nearest valid increment.
  • When another positional snap determines an exact location, that snap takes precedence over numeric distance rounding.
  • Orbit resizing works in both directions: if the resize cursor is near an eligible Planet, Moon, or Point and the ring reaches that node, the ring snaps to the node's exact center distance and the node immediately adopts the orbit's anchor as its orbital parent. Nodes elsewhere on the same ring are ignored unless they are also near the cursor.
  • The default visual conversion is 500 km per map unit, matching the working 2 visual units per 1,000 km baseline. The scale field can be changed per layout.
  • km-authored orbits preserve their km value while the editor converts their visual radius.
  • Orbit cards can be reordered and deleted from the sidebar.
Routes
  • Create Route in the sidebar lets you choose endpoints and enter travel distance directly.
  • Route distance can be authored in km or map unit. Double-click the visible unit label beside a route distance to toggle between them. This works in Create Route, node route rows, and the map route editor.
  • On the map itself, single-click the route-distance label to toggle its inline editor open/closed; double-click the distance label to toggle its passive positioning guide without changing the authored number.
  • Map-unit routes retain their authored map-unit value and derive km using the layout's km-per-map-unit scale; older routes default to km.
  • Hold Ctrl, click-drag from a Planet, Moon, Slipstream, or Point, and drag toward another valid node to draw a route interactively.
  • The route endpoint snaps when the cursor is close enough to a valid destination.
  • Release over the highlighted destination while Ctrl is still held to create the route.
  • Release Ctrl, release away from a valid destination, or press Esc to cancel route drawing.
  • After a drawn route is created, its distance field is automatically focused so the km value can be typed immediately.
  • Connected routes appear in each node card and are also mirrored into Selected Object for the currently selected node. Distance, unit, and delete controls work from either location.
  • Each node with connected routes has a Live route distance toggle in both Selected Object and its node card. ON recalculates connected travel distances when that node moves; OFF freezes the authored travel-distance values so map geometry and route distance can intentionally differ.
  • The ☰ menu also includes a global Live route distance — all nodes master checkbox. It acts as Select All / Select None for every node; if per-node settings are mixed, the master control appears indeterminate.
  • After using the global master control, individual node toggles remain available so exceptions can still be configured.
  • The Live route distance choice is stored per node in JSON and defaults to ON for older layouts.
  • The setting applies to mouse dragging, direct coordinate edits, movement inherited from a parent, orbit resizing that carries the node, and snapping/re-parenting movement.
  • When Live route distance is ON and a node is moved, connected route distances follow the live geometric separation. They snap to the nearest 0.1 map unit or equivalent km; hold Shift while moving to use the unsnapped geometric distance.
  • If both endpoints move at once, a route updates when at least one moved endpoint has Live route distance enabled. If every moved endpoint on that route has it disabled, the authored distance remains unchanged.
  • Positional snapping overrides distance snapping. If a node snaps to an orbit, connected routes use the exact orbit-snapped geometry rather than rounding that result to the distance grid. Likewise, Ctrl-drag routes snapped to a destination object use the exact endpoint separation.
Distance guides, route targets & solar planning

Guides are passive overlays. They move only their own lines, rings, labels, and numbers; they never reposition planets, moons, points, stars, or orbit rings.

  • Route target overlay: selecting any node temporarily shows the authored-distance target overlay on every route connected to that node. If you then select/drag the orbit that node is attached to, those same route targets remain visible while the orbit is resized.
  • Orbit route context: selecting or resizing an orbit uses the bodies currently attached to that orbit as the route-guide context. This lets a moon or planet keep its route-distance reference visible while you adjust the orbit radius.
  • Context cleanup: while a node or orbit is selected, only route guides relevant to that active node/orbit context are shown. Persistent/manual guides belonging to unrelated bodies are temporarily hidden, preventing a previous moon's target line from lingering while another body is being edited.
  • Selected-node route target: the selected/attached body's center becomes the fixed reference cap. The guide lies directly over the route axis, passes through the current connected-node center, and extends to the authored target center when needed. The far perpendicular cap is therefore the exact center position where the connected node would satisfy the authored route distance.
  • Manual-only route target: when nothing is selected, an explicitly activated manual guide keeps its original persistent midpoint-based behavior.
  • Route target caps: each short perpendicular cap represents a node center, never the outer edge of a node. Yellow means current center-to-center geometry differs from the authored target; green means it matches within the editor's precision tolerance.
  • Map route label shortcut: use the blue bordered distance pill drawn directly on the route line (for example, 8,000 km). Single-click that pill to toggle its inline editor open or closed. Double-click the same pill to toggle the positioning guide using the route's current authored distance exactly as if that number had just been entered manually.
  • Double-clicking an already active route guide turns it off immediately. This is the manual counterpart to the guide automatically disappearing after a successful green-match drag release.
  • While a manual route guide is active, that route's authored distance is temporarily protected from Live route distance recalculation so it remains a stable positioning target.
  • If the line is green when the mouse is released after moving one of its endpoints, the guide automatically turns off. If it is still yellow, the guide remains visible for the next positioning attempt.
  • The small Guide × control beside an active route can dismiss the guide without changing the route or node positions.
  • Star-centered bodies: selecting a planet, moon, or orbital point whose parent is the star (or which is unattached) uses the normal passive center-to-center stellar ruler and suggested star-distance logic.
  • Parent-centered satellites: when a moon or orbital point is attached to a non-star parent, its local orbital distance is measured to that parent—not to the star. A direct child↔parent route distance is used as the fallback parent-distance target; if no such route exists, the current assigned-orbit radius is used.
  • If an attached satellite also has enough temperature/Solar power in orbit data to derive a preferred satellite→star distance, the editor combines that target with the actual parent→star distance and the satellite→parent orbit radius to solve a suggested angle around the parent.
  • The satellite angle uses the law of cosines: with A = parent→star, B = satellite→parent, and C = desired satellite→star, the editor solves cos(θ) = (A² + B² − C²) / (2AB). There are two mirrored positions on the orbit; the editor chooses the one closest to the satellite's current angular position.
  • The resulting ghost node is only a positioning suggestion on the satellite's existing orbit. The guide never changes the orbit radius or moves the real satellite automatically.
  • No satellite ghost is shown until the node is actually attached to an orbit. If the preferred stellar radius is unreachable at the current parent-orbit radius, the ghost shows the closest achievable starward/anti-starward position and labels the target as unreachable.
  • If climate data is missing or insufficient, the editor does not invent an angle. It falls back to the existing child↔parent route distance when available, or the current orbit radius otherwise.
  • Contextual orbit suggestions: suggested orbit-distance rings and map labels are not shown permanently. With the View option enabled, they appear when the related planet, moon, orbital point, or star-centered orbit is selected, when the guided node is dragged, or while the orbit is resized. They remain independent from the star-distance/solar measurement toggle.
  • Route-distance suggestions: View → Show suggested route distances independently controls the route target spine, target node-center caps, and target label. Turning it off does not hide normal route lines or their blue distance pills.
  • The suggested-distance ring, star↔body measurement ruler, orbit suggestion ticks, and satellite positioning guides use reinforced strokes for readability while remaining passive overlays.
  • Dynamic map labels: route-distance pills and passive guide labels reserve nearby node/name/info regions and automatically try alternate nearby positions when the default placement would overlap existing UI. When a label is displaced, a short leader line points back to the route/guide location it describes.
  • This is especially useful for short routes inside small moon orbits: the route-distance pill may sit outside the crowded orbit while a leader line keeps its relationship to the route visually clear.
  • Orbit-resize preview: while click-dragging a star-centered orbit ring, every attached planet, moon, or orbital point with temperature or solar guide data temporarily shows the same star-distance ruler and, when contextual suggestions are enabled, its suggested-distance ring. The overlays update live as the orbit radius changes and disappear when the mouse is released; they never move anything independently.
  • Planets, moons, and orbital points can store Solar power in orbit (%) alongside temperature. Solar power in orbit is one input to the suggested star-distance calculation. Higher percentages generally imply a closer stellar distance and lower percentages a farther one. The sample profile uses its own calibration anchors rather than treating 100% as a universal reference point.
  • Solar power in atmosphere (%) is intentionally separate. It does not change orbital positioning. Solar power in orbit (%) is the value used to derive the preferred distance from the star; atmospheric solar is only used for the climate/atmosphere diagnostic.
  • Migration safety: layouts using the original solar_power_percent field are interpreted as atmospheric solar because that field was originally presented as “Solar power in atmosphere.” It is no longer copied into Solar power in orbit. Layouts using the intermediate solar_power_in_space_percent field migrate to Solar power in orbit but are flagged for review because older files may have inherited that value from the original ambiguous migration.
  • Existing solar_power_in_orbit_percent values from older editor versions are also flagged until explicitly confirmed, because a layout re-saved during the bad migration may already have lost the original field provenance. Re-entering/editing Solar power in orbit marks that value as confirmed and clears the warning.
  • The climate diagnostic compares Solar power in atmosphere against Solar power in orbit to produce a transmission proxy. It also calculates a simple atmosphere-solar temperature proxy using T ∝ F^(1/4) with 288 K at 100% atmospheric solar as the planning reference. This climate reference is separate from the orbital-distance calibration.
  • If an observed planet temperature is available, the editor reports the difference from that solar-only estimate as a climate residual and describes it as apparent cooling, near-baseline, or apparent warming.
  • The transmission and climate residual are planning diagnostics only. They do not determine specific greenhouse gases or atmospheric composition; albedo, clouds, pressure, emissivity, internal heat, oceans, and other effects are not modeled.
  • Vanilla Nauvis (default): Nauvis uses 300% Solar power in orbit and 100% Solar power in atmosphere. Those two percentages are the vanilla Factorio values. The default 288 K temperature and 7,750 km reference distance are editor planning references because vanilla Nauvis does not expose an orbital-distance/planet-temperature pair for this calculation.
  • Model selector: Edit → Solar / Temperature Model Editor defaults to Vanilla Nauvis. It also includes Inverse-square / equilibrium, the sample calibrated model, and saved/imported custom models.
  • Numeric model edits: changing any model number immediately switches the active model selector to Inverse-square / equilibrium and uses those edited values as the current custom inverse-square model.
  • Save / Load in Edit: Save Model stores the current model under a name; Load Model re-applies the model selected in the Edit-window dropdown. The same models remain available through Save / Open → Solar / Temp Model.
  • Drag-and-drop models: dropping a valid Solar/Temperature model JSON anywhere on the editor is recognized separately from a system JSON. The model is added to the available model list, applied immediately, and the Edit window opens so its values are visible.
  • Model files: when a Models folder is configured, saved models use .fsse-model.json files and are populated into the dropdown from that folder. Without a folder, custom models are saved in browser storage and can still be exported/imported manually.
  • Sample calibrated profile: the editor also includes a separate example anchor profile using 600% ≈ 4,250 km, 300% ≈ 7,750 km, 200% ≈ 9,842 km, and 120% ≈ 12,000 km plus its example thermal anchors.
  • The sample thermal curve uses 371 K ≈ 3,500 km, 320 K ≈ 5,020 km, and a 288 K temperate band spanning roughly 5,711–7,624 km. Temperatures below that band extend outward with the simplified T ∝ d^-1/2 relationship. Treat this as example calibration rather than a universal climate model.
  • Inverse-square / equilibrium is the default calculation mode for the Nauvis model. Solar uses d = dRef × sqrt(PRef / P). Temperature uses its own editable temperature and distance reference with d = dTemp × (TRef/T)^2.
  • When both solar percentage and temperature exist, the editor displays the solar estimate, thermal estimate/band, and a geometric-midpoint planning suggestion. This is a layout heuristic, not a climate simulation: albedo, atmosphere/greenhouse effects, emissivity, and internal heating can make temperature differ substantially from a simple orbital estimate.
  • For star-centered orbit rings with guided planets, moons, or orbital points attached, the map and orbit card show a suggested ring-distance label. Multiple guided bodies on one ring show a shared midpoint and range rather than moving the ring.
  • Use ☰ → Distance Guides to switch between the sample calibrated profile and inverse-square model, edit inverse-square reference values, or hide/show star-distance/solar overlays. Manual route target guides remain explicit route-authoring aids.
Selection, deletion, copy & paste
  • Click a node or orbit to select it and edit its properties in Selected Object.
  • For any selected node, Create orbit around <node type> creates a new orbit centered on that selected node itself. The selected node's own Parent and Orbit controls only describe where that node orbits; they do not choose the center of the new orbit created by this button.
  • Selected nodes use a distinct outline and bold map-name label. Only the node body receives the selected/snap/lock outline styling; thermometer and solar annotation icons keep their normal shape. This applies consistently to planets, moons, slipstreams, points, and stars.
  • A small vector lock-state icon is displayed between each map node and its name. A closed lock means the node's position is locked; an open lock means it is movable. The indicator is informational only and never intercepts selection, dragging, or rename input.
  • Double-click the actual node body to toggle its position lock. Double-clicking the node name still enters rename mode, so locking and renaming remain separate gestures.
  • Text and number edits use commit-on-blur: typing does not update map geometry or derived values until that field loses focus. Clicking elsewhere, selecting another node/orbit, or pressing Tab/Shift+Tab commits the edit.
  • Inside Selected Object, Tab commits the current text/number field, then moves to the next text/number field; Shift+Tab moves backward. Checkboxes, selects, color pickers, and buttons are skipped by this focused data-entry traversal.
  • Whenever a text/number field receives focus by mouse or keyboard, its populated value is automatically selected so the next keystroke can replace it immediately.
  • Numeric fields include up/down spinner controls. ↑/↓ or the spinner buttons adjust the current displayed value and are the deliberate exception to commit-on-blur: each step updates the drawing immediately while returning focus to the same field with its contents selected.
  • Numeric step sizes are universal in the field's current displayed unit: ↑/↓ = 1, Ctrl+↑/↓ = 5, Shift+↑/↓ = 10, and Ctrl+Shift+↑/↓ = 100.
  • When a different node or orbit populates Selected Object, route-distance and orbit-radius units initialize to km, matching the distance information normally shown in-game. You can still switch that selected object to map units afterward; the unit is only reset to km when a new selection populates the editor.
  • Planet, moon, and orbital-point map annotations show temperature and, when available, Solar power in orbit (%) with a small sun icon beneath the body.
  • Alt map-info toggle: press Alt to show/hide attached temperature/Solar power annotations. The default is on. The current state is stored as metadata.show_node_info_overlays, so imported JSON/autosave restores an off state instead of forcing the overlays back on.
  • For nodes, Selected Object mirrors the relevant editable information from that node's sidebar card rather than moving the original card. The mirror is intentionally flat and card-like: title/meta at the top, compact property rows, orbital information, Live route distance, a divider, route rows, then remaining object controls—all inside one panel rather than nested boxes.
  • The mirrored controls include name, coordinates, temperature where supported, star size/color where supported, orbital parent/orbit assignment, Live route distance, connected route distances/units/deletion controls, type, and lock state.
  • Edits made in either the Selected Object mirror or the original node card update the same underlying object. Normal typed text/number edits synchronize when committed on blur/Tab; numeric arrow/spinner stepping and other live controls synchronize immediately.
  • For nodes with routes, Selected Object also includes the per-node Live route distance toggle so route values can either follow geometry or remain independently authored.
  • Delete or X deletes the selected node/orbit. The permanent star is protected.
  • Ctrl+C / Ctrl+V copies and pastes the selected node or orbit when focus is not inside a text field.
  • The star cannot be duplicated or deleted.
Star appearance
  • The star's rendered size can be edited numerically or by selecting it and dragging its graphic.
  • Star color can be entered as a hex value or chosen with the color picker in the star's node card.
  • Star color and size are saved in the layout JSON.

JSON, import/export & editor data
  • Export JSON downloads the current layout. Copy JSON copies it to the clipboard. Import JSON loads a selected JSON file.
  • The JSON stores node order, orbit order, routes and route units, active manual route-guide state, orbital relationships, per-node Live route distance behavior, temperature, solar-power-in-orbit, and solar-power-in-atmosphere guide values, star appearance, orbit-unit, guide-model, contextual-suggestion, guide calibration metadata, and legacy solar-migration review flags, system title, and editor viewport.
  • The global Live route distance master control is derived from the per-node settings and is not stored as a separate layout property.
  • Legacy layouts are normalized when loaded; older moon relationships can be migrated where the editor has enough information to infer them safely.
  • Temperatures are optional reference values for planets, moons, and orbital points and can be filled from whatever source data the layout is based on.
  • Temperature annotations use a vector thermometer icon so the symbol stays aligned consistently with its value across browsers and operating systems.
